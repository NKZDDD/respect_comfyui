# 批量客户端接入服务端适配包

客户端版本：2026.11.03.2。日期：2026-11-03。

## 原因

此前批量版只读取服务端的账号、Key 和模型授权，仍由内置的 17 家适配器执行请求和提供参数。Studio 后台发布适配包不会改变批量端的实现。部分内置 image.max_refs 为 0，后台绑定的新型号可能继承这个默认值，在提交之前就被批量端拦截。

## 本次行为

- 批量与 Studio 使用同一份协议 1 适配包。验证账号时读取 adapter_config，再带登录凭证与构建信息调用现有 /api/v1/auth/adapters。
- 接收后校验规范化 SHA256、协议、版本和授权服务商列表，再加载包内 Python 实现。缓存只在本次在线授权的校验码吻合时复用，不能离线授权。
- 登录、手动“刷新后台配置与模型”、在线校验发现适配包变更，都会同步。页面显示当前适配包版本。
- 模型按后台 Key 绑定或该适配器的模型清单显示。参考图上限、比例、尺寸等使用适配包能力声明；显式 0 表示不支持参考图，None / refs_unlimited 表示不设本地张数限制。
- 不再把服务商实现打进在线授权安装包。包缺失、不完整、校验失败或依赖不兼容时，拒绝新任务，不悄悄回退到旧内置实现。
- 已开始批次绑定原适配包代码。刷新不替换正在运行的类，不重新提交已发任务；账号及 Key 授权仍在提交前校验。
- 同步新版适配器需要的公共 HTTP、图片格式和参考图处理接口；包括自带 HTTP 调用的适配器在内，生成尝试仍归属当前账号和具体 Key。

## 更新方法

1. 现有服务端已有适配包接口，本次不需要覆盖服务端程序。
2. 在后台“服务商适配包”确认当前包已发布，并包含分配给账号的所有服务商。
3. 在“客户端版本”选择“对外批量版”，登记新包 batch-registration.json；需要推更时导入对应 release.r2.json，再设置推荐或强制更新。Studio 的版本策略独立。
4. 批量客户端升级一次到 2026.11.03.2，登录后确认顶部适配包版本。之后更新兼容现有运行库的适配代码，只需后台发布，再刷新客户端配置。

2026.10.29.1 / 2026.10.29.2 存在旧的 HTTPS 打包问题，首次修复需手动安装。已安装 2026.11.03.1 的用户可以使用现有更新功能。适配包引入新第三方依赖或新协议时，仍需升级通用客户端运行库。

## 验证及边界

138 项测试通过，包含 Windows 安装交接、适配包校验失败拦截、切换账号、刷新与执行中版本隔离、原有用量对账及请求路由回归。

当前 Studio 导出的全部适配器在批量运行库中加载通过。真实沧元适配器的离线测试验证了 15 张参考图进入 edits 请求、返回 JPEG 转成 PNG、模型及 Key 正确、仅记录一次完成事件。请求由测试替身返回，没有付费生图。

浏览器验收验证刷新更新适配包版本和参考图限制，并区分 0 与不设本地上限；无脚本报错。未使用真实用户密码，未将离线模拟测试表述为各家上游已实测生成成功。

Key 与上游地址仍由客户端在内存中使用，请求仍是客户端直连。适配包是管理端发布的可执行代码，本次没有将生成请求迁移到服务器代理。
