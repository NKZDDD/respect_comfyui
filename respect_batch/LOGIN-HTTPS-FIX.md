# 批量客户端 HTTPS 登录修复

2026-11-03，用户反馈已发布批量版提示“登录服务连接失败，请重试；已发任务不会重新提交”。

## 原因

线上认证服务 1.11.2 正常，2026.10.29.2 的批量版本与构建校验均放行。但实际发布的单文件 EXE 和 standalone 程序都无法登录或检查更新。

编译使用的 Python 运行时修改了 `ssl.SSLContext.__new__`，初始化时会读取同目录 `codex-rejected-cas.pem` 信任策略文件。Nuitka 自动打包了 certifi 的普通根证书文件，却没有发现这份额外运行时数据。SSLContext 初始化因此抛出 FileNotFoundError，被 requests 包装为 ConnectionError，客户端显示统一的连接失败提示。与账号、Key 分配或服务器版本登记无关。

此前发行包验收仅检查本地页面、未登录拦截和缺少构建清单时的拒绝路径，网络调用数为 0，未发现实际 EXE 的 HTTPS 初始化缺失文件。

## 修复

构建器识别当前 Python 的证书信任策略伴随文件并一同打包，保持原有证书校验及信任策略。客户端升级为 2026.11.03.1；没有关闭 TLS 校验、修改服务端账号或版本策略。

旧包的更新检查也受影响，首次升级需手动安装修复包。新构建需要管理员在“对外批量版”中登记后使用。已有 Studio 安装、项目、配置与已提交任务不受本次安装器替换影响。

## 验证

最小 HTTPS 编译程序复现相同 FileNotFoundError；仅补入该文件后，服务端健康接口返回 HTTP 200。同一份 standalone 批量程序补文件后可获取更新配置，并收到认证服务正常的构建未登记提示（standalone 文件哈希与已登记单文件 EXE 不同）。

修复版实际单文件 EXE 已收到线上登录接口的 HTTP 426 构建未登记响应，并成功解析更新接口的版本策略；说明 HTTPS 初始化和传输已恢复。新版本尚未在服务端登记，所以没有宣称真实账号已登录成功。完整测试 130 项通过，含 Windows 静默安装交接测试。
