# 批量客户端模型读取与识别修复

日期：2026-11-04。

用户请求：“把这个问题完成修改，是否需要用到什么key”。截图提示 CY 模型读取失败、NY-vale 有模型类型无法识别。

## 定位

截图来自 `respect_batch`，提示由 `core/managed_models.py` 生成，并非 Studio 的生产页。

在线授权批量版已加载服务端适配包，但读取模型时调用继承的 `Provider.list_models()`。
这个方法只返回模型 ID，把接口的类型和逐模型参数丢掉，同时将 `ApiError` 吞掉并返回空列表。
上层因此只能依靠名称猜类型，也无法区分鉴权、超时和真正的空目录。之前测试覆盖了后台显式绑定模型和适配器加载，未覆盖实际适配器使用默认目录接口的完整路径。

这些是可复现的代码缺陷；不能单凭截图认定 NY 具体哪个模型缺少类型，也不能认定 CY Key 已失效。
本机已有的沧元 Key 在本次只读检查中成功返回 120 个模型，但未确认它与截图账号分配的 Key 相同。

## 修改

- 默认目录读取保留类型和逐模型能力字段，只保留允许的模型字段，不回显原始响应或异常内容。
- 保留适配器自定义 `catalog_rows` / `list_models`，并执行 `filter_catalog`，避免丢失特有目录规则。
- 区分图片、视频与明确声明的文字、音频等类型；同步已有 Studio 的 Midjourney、Omni、Lyria、Suno 名称规则。
- 真正未知的条目提示数量与模型名，说明已列出的模型仍可选择，不再笼统要求升级客户端。
- 目录请求失败分别显示 HTTP 状态、超时、HTTPS 连接、网络连接、JSON、目录格式或空目录原因。
- 后台显式模型绑定仍优先；不回退其他 Key 或全量静态目录，同模型仍使用排在前面的已授权 Key。

范围是批量客户端公共目录读取和授权模型汇总；未修改 Studio、服务端、账号授权或服务商生成协议。

## Key 与使用

修代码、自动化回归不需要真实 Key。运行时仍使用后台分配给账号的服务商 Key，不需要新增特殊 Key。
本次沧元只读验证使用本机已有配置，未发起付费生成。NY 未进行带真实 Key 的线上验证。

本修复在客户端代码中，已安装 EXE 不会自行改变，需要重新构建并安装批量客户端后生效。
此次未打包、上传 R2 或修改线上发布策略；仅发布服务商适配包不能替换客户端的目录读取代码。

- 沧元真实只读目录查询：120 个模型，40 个识别为图片类型；生成请求数 0。

修复后，新模型如果返回了类型和参数，会按这些信息展示；目录失败会给出具体原因。
仍未提供可识别类型的模型会列明名称，避免把一个不支持的条目误认为当前选中的图片模型不可用。
