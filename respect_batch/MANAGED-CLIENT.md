## 管理员

1. 登录服务至少需要 1.10.2，支持 `batch`（批量创作）版本类别，原账号和 Key 库不变；已经使用更新服务端的，不要降级。
2. 构建客户端后，在“客户端版本 → 测试登记”导入 `batch-registration.json`。此操作不推送 Studio 更新。
3. 在原 Key 库命名 Key、绑定模型，再给账号勾选条目。一个服务商可以分配多把 Key；重叠模型按后台排序选择第一把，不做失败换 Key。
4. 未绑定模型时按每把 Key 查询模型；查询失败不会回落到其他 Key 或全量模型目录。
5. 使用公网图片参考的模型需要给账号分配原有 R2 上传权限。客户端只请求短期上传链接，不接收 R2 长期凭据。现有服务端不支持参考视频上传，勿给这类任务添加参考视频。
6. 在账号“用量对账”中按 Key 和时间查看记录及导出 CSV；导出的模型列可用于分模型核算。

本版不再内置服务商实现。后台“服务商适配包”发布的同一份协议 1 包用于 Studio 和批量版，按账号授权下载。登录、手动刷新及在线校验发现包变更时同步代码与模型能力；后台必须已发布包含账号所需服务商的适配包。更换现有运行库支持的适配器不必重新打包；引入新的第三方运行库或包协议仍需要升级客户端。缺包、校验失败或依赖不兼容会阻止新任务，不回退旧的内置限制。
同一账号在 Studio 与批量版使用同一组授权；现有后台用量按账号合并，尚未增加按应用分账。可以给批量用户创建单独账号。

## 用户

在「按任务范围分配成品文件夹」中填写起止行号，点击「选择文件夹…」选择本机目录或可写的共享目录，也可以直接粘贴完整路径。点「分配文件夹」后，该范围的任务会输出到选定位置。只填名称时会在成品主目录下创建子文件夹。选中范围后点「恢复到成品主目录」即可撤销分配。

推荐运行 `Respect-Batch-Setup-2026.11.06.1.exe` 安装，从“Respect 批量创作”快捷方式启动。便携使用时将 `RespectBatch-User.exe` 和 `batch-build.json` 放在同一目录。使用管理员提供的账号登录。
页面只显示已授权模型和名称，不提供服务商地址、个人备用 Key 或导入配置入口。
点击“刷新后台配置与模型”同步管理员变更。正在跑的批次先停止新任务并等待收尾，再刷新或切换账号。
批次运行期间可以换模型继续提交，也可以在进度区点“新建空白批次”。在“查看批次”中选择要看进度、停止或取回成品的那一批。每批按提交时的模型、参考素材、任务和并发数执行，同一服务商的配额和账号并发限制跨批生效。同目录下不同模型的同名成品用后缀区分，同一模型同时写入同名成品时附加批次编号。列表保留运行中、可重新下载以及最近完成的 30 个批次，运行记录仍保存在磁盘上。
每次新批次强制在线校验，排队中的任务提交前复查账号及 Key 授权；已发任务继续取回，不因登录失败重新生成。
点击“软件更新”可检查、下载并查看进度，校验通过后点击“重启完成更新”。启动会检查版本，强制更新后登录前也能更新。有运行任务时先等待收尾。安装器只替换批量程序和版本文件，不覆盖 Studio 或用户数据。首次从 2026.10.29.1 升级须手动安装本次安装器。

用量按生成尝试计一条，适配器自带 HTTP 调用也会记入当前账号和 Key；轮询和重复上报更新同一事件。明确失败可按设置重试，每次新提交分别记账。
已返回任务 ID 后取回失败记“待取回”；网络中断等不能判断是否提交成功时记“结果不明”，不自动重发。
跳过已有成品、未授权和上传前失败不增加生成次数。
记录暂存在 `%LOCALAPPDATA%/Respect-Batch-User/usage-outbox.sqlite3`，连接恢复且原账号登录后补传。启动后中断中的事件转为待确认，不伪装成失败。
客户端上报只供对账，不是服务商实际扣费证明。故意修改或绕开客户端的调用无法靠这些记录保证覆盖。

## 联网设置（2026.11.06.1）

登录前及主界面右下角均可打开“联网设置”。本机设置独立保存于 `%LOCALAPPDATA%/Respect-Batch-User/network.json`，切换账号、刷新后台配置不会覆盖它。

- **跟随系统代理（默认）**：读取系统手动代理、HTTP_PROXY / HTTPS_PROXY / ALL_PROXY 环境变量及绕过规则；没有代理时直连。系统代理变化从后续请求生效，环境变量需重启程序后读取。PAC 自动配置脚本不受支持，可改用指定代理地址。
- **直连**：忽略应用代理，直接连接目标。系统层 TUN / VPN 仍可接管流量。
- **指定代理地址**：例如 `http://127.0.0.1:7890`，填代理软件实际提供的 HTTP / HTTPS 地址和端口，先启动对应软件。暂不支持 SOCKS、代理账号密码或 PAC；连接失败不会偷偷切回直连。

统一作用于登录、授权刷新、用量上报、适配包和模型目录读取、生成、查询、参考素材上传、成品及更新包下载。已有适配器通过 Requests 发起的独立请求也遵循此设置；公开成功率统计使用同一选择，失败不影响生产。

保存不会创建任务或自动刷新授权。已登录可点击“刷新后台配置与模型”重新拉取目录；连接恢复后继续查询原任务。正在传输的请求不会被强行中断，后续请求使用新线路。原有重试规则保持：明确未发送的请求可按设置重试；提交结果不明时不自动重发或换线重提。

此前模型目录和生成请求被固定为直连，即使登录和浏览器能通过系统代理访问，生成链路也可能在 TLS 握手时被重置。新增选择允许用户使用实际可用的网络路径，但不能保证任意代理能访问上游。HTTPS 证书校验、后台模型/Key 授权、更新包哈希和原有重定向限制均保留。

此修改仅针对在线授权批量客户端，不改变 Studio。已有 EXE 和服务商适配包不会自动获得此入口，需要构建并安装新批量客户端；不需要更改服务端配置或提供另一把 Key。

源码验证（2026-11-06）：完整回归 222 项通过，1 项可选的 Windows 安装器实测当时未启用；打包 Python 环境的联网及统计检查 48 项通过。已核对登录前入口、桌面与窄屏布局、代理保存与读取、适配器请求和已提交任务换线查询。没有发起付费生成，仍需在原故障电脑使用可用代理验证 CY 链路。本次构建、安装器与上传校验结果以交付目录 VALIDATION.json 为准。

## 2026.11.09.1：参考图预览与结果下载修正

共用图、单条图和素材库图各自展示缩略图。单条图改为在提示词下方换行展示，预览读取失败时显示“预览失败”；后台配置刷新后重绘素材库，删除素材库不再残留旧的导入成功提示。使用真实本地上传、登录 Cookie 和文件预览接口验证了文件夹导入两张图。客户确认版本为 2026.11.07.1；该发布包页面在本机也能正常预览两张图。“刚选完即全空白”的完整触发条件尚未复现，需要该次任务清单确认图片是否实际进入任务；不能将已发现的旧提示残留当成该现象的根因。

## 2026.11.09.2：登录后拖拽共用参考图丢失

客户补充触发方式为从微信拖拽到网页。浏览器回归已复现一个共用拖拽缺陷：页面初始化时拖拽事件持有旧的参考图数组，登录成功后数组被替换，拖入文件虽上传成功，却加入旧数组，当前预览和任务参数均读不到；点击文件选择框不经过这条旧绑定。此问题同样影响普通文件拖拽，不只微信。

改为在每次放下文件时读取当前参考图列表，图片、视频任务共用同一修正。没有传来文件、只传来链接等拖拽内容时，明确提示先另存图片后导入，不再静默无响应。浏览器回归覆盖退出再登录、共用和单条拖入、无 MIME 类型的图片文件、后台配置刷新及真实本地上传/缩略图读取；未在客户微信版本上操作验证。此修改从 2026.11.09.2 开始包含，已上传的 2026.11.09.1 安装包没有此修正。
