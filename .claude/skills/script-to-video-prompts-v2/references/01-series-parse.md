# 环节 1-3：整剧全局解析 → 15秒段落划分 → 状态时间线管理

三个环节共同构成整个体系的数据基座。产物全部落盘到 `01_项目信息/解析数据/`。

---

# 环节 1：整剧全局解析

## 目标

理解完整故事、建立全剧时间关系、识别所有故事实体、建立资产演化基础。

**输入是「整剧」不是「单集」** —— 资产由整部剧决定。第 3 集才揭晓的疤痕、第 8 集才砸毁的房间，都必须在解析阶段就进入演化图，否则资产库会在中途返工。

## 输入

- 完整系列剧本（理想）或单集结构（受限模式，见范围标记）
- 项目基础信息（片名、集数、单集时长、目标平台竖屏/横屏）

## 核心处理（四个平面）

**1. 全剧时间线**
- 事件顺序、平行事件（双线叙事标注「同时发生」）、时间跳跃、因果关系

**2. 实体识别**
- 人物、场景、道具、群体（如「围观顾客」）、附属特征（胎记/疤痕/标志配饰——这类是身份识别锚点，单独列出）

**3. 事实识别**（四类分开记，防止把「说法」当「事实」生成画面）
- 客观发生事实 / 人物说法 / 梦境或幻觉 / 未确认信息

**4. 资产演化**
- 人物阶段变化（长期）、人物造型变化（短期）、场景长期变化、道具状态变化，每项标注**变化有效范围**（从第几集第几段起）

## 输出（全剧解析数据包）

| 文件 | 内容 |
| --- | --- |
| `timeline.json` | 全剧时间轴（含平行事件标注） |
| `entities.json` | 实体主表 |
| `change_events.json` | 变化事件表 |
| `asset_evolution.json` | 资产演化图 + 版本有效范围表 |
| `conflicts.json` | 冲突与未确认信息表（剧本自身矛盾、留白，供人工裁决） |

## 范围标记（scope）—— 强制

```
full_series + canonical      完整系列解析 → 项目级最终定论
full_episode + provisional   只有单集 → 暂定结论，后续集数到位必须复核
test_sample  + local_only    测试片段 → 只在测试命名空间生效
```

核心规则（原文）：

> 只有完整系列分析结果，才可以成为项目级 canonical 最终结论。
> 测试案例产生的通用规则可以进入系统，但案例资产结论只在测试命名空间生效。

## 项目视觉基调（归入 01_项目信息）

作为「项目生成配置」的一部分，只定一次，后续所有资产提示词与段落提示词继承。模板沿用十项结构（类型定位/氛围/色调/光影/人物质感/场景质感/镜头构图/画质技术/禁止项/参考气质），并产出**压缩版一行描述**供提示词直接拼接。多地点强反差的剧（如底层线 vs 顶层线）按线出多个压缩版变体。

> 视觉基调 + 范围标记 + 时间轴 + 实体主表 = 环节 1 结束后唯一的人工确认点。

# 环节 2：15秒段落划分

## 目标

把完整剧情切成可独立生成的 15 秒段落。**时长固定 15 秒**——情节撑不满/超出就调整该段承载的内容量，不改时长。

## 切段原则（原文）

> 一个段落应尽量形成完整的小章节。
> 复杂动作尽量不要被截断在两个段落之间。
> 跨场景、跨时间或重大资产变化，优先作为新的段落边界。

补充判断量：一段 15 秒通常容纳 2~3 句对白、1 个情绪节拍。对白超过 3 句的剧情要么拆段，要么把配角台词降级为环境议论声。

## 每段字段

```
segment_id              EPxx-SEGxx
narrative_objective     本段叙事目标（一句话）
required_story_beats    必须呈现的剧情点（列表，漏一个都算失败）
original_actions        原始剧本动作（原样保留）
original_dialogues      原始对白（原样保留，标说话人）
start_condition         开始条件（画面从什么状态开始）
end_condition           结束条件（画面停在什么状态）
forbidden_future        绝不能提前出现的后续剧情元素（防剧透列——如"SEG03之前不能出现白粥"）
```

`forbidden_future` 从全剧时间轴反推：凡是后续段落才揭晓/才发生的视觉元素，在本段都要显式列为禁止项，并最终写进本段两种提示词。这是「提前生成后续剧情结果」检查项的数据来源。

输出：`segments.json`（15秒段落表）。

# 环节 3：状态时间线管理

## 目标

记录剧情世界在每个段落前后处于什么状态。**这是段间衔接的唯一机制**（本体系没有首帧链）。

## 核心关系（原文）

> 上一段退出状态 = 下一段进入状态
> 指客观状态一致，不要求前后画面构图完全相同。

生成每段的进入状态时，**先复制上一段的退出状态再增量修改**，不要重新描述——重写就会漂移。

## 状态分类

| 类 | 定义 | 例 |
| --- | --- | --- |
| 进入状态 | 段开始时已存在的事实 | 小腿有干涸血迹、地面有碎玻璃 |
| 持续状态 | 跨多镜头/多段保留 | 外面在下雨、制服被拖动后凌乱 |
| 退出状态 | 段结束后形成的结果 | 晕倒在地、后脑磕伤 |
| 不可逆事实 | 不能无原因恢复 | 疤痕、房间被砸、身份暴露、已公开的信息 |
| 临时状态 | 段内即时表现——**永远不做成资产** | 动作、表情、站位、持有关系、短期伤势 |

## 状态对象（每段逐项记录）

- 人物身体状态、人物情绪趋势、人物位置
- 道具持有人、道具当前状态
- 场景持续变化
- 已经公开的信息（谁知道了什么——防止剧情逻辑穿帮）

## 输出

`states.json`（段落状态包），每段形如：

```json
{
  "segment_id": "EP01-SEG05",
  "entry_state": {
    "C001": "站于货架前，右小腿有渗血划伤，情绪压抑濒临崩溃",
    "C002": "近身逼迫姿态，面部涨红",
    "P001": "碎裂状态，玻璃碎片与果汁洒在C001脚边地面",
    "S001": "深夜卖场，地面有碎瓶狼藉",
    "public_info": "围观者已开始拍摄"
  },
  "persistent": ["右小腿伤口(本集有效)", "地面碎瓶(本集有效)"],
  "exit_state": {
    "C001": "低血糖发作，脸色惨白，即将失去意识",
    "...": "..."
  },
  "irreversible": [],
  "temporary": ["绞紧衣角", "指节发白", "泪水打转"]
}
```

**校验**：跑完全部段落后，机械比对每对相邻段的 `exit_state` / `entry_state`，不一致的列出来当场修，不带病进入环节 4。
