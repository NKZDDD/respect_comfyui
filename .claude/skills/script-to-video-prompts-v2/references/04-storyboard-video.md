# 环节 9-10：段落故事板生成与固定 → 视频执行生成

两个环节实际出图出片（默认模型：故事板 = GPT Image 2，视频 = 即梦2，可换）。提示词与参考图绑定已在环节 8 全部编好——**这两个环节不生产任何新内容，只执行**。

**生产执行是可替换模块**：本环节消费环节 8 的 `tasks.json` + 提示词文件，产出约定路径的文件 + 注册表登记——满足这个契约的任何执行器（Agent 直调中转站 API / ComfyUI 工作流 / 平台手动操作）等价可换，背后甚至可能是同一个模型。Agent 直调时复用 `utils.py` 的 `api_request` 体系（提交 → 轮询 → `download_to_output` 落盘），技术检查（格数/顺序/身份混用/损坏）Agent 读图完成——都在「客观技术检查」允许范围内。

# 环节 9：段落故事板生成与固定

## 单次任务组成

```
一个SEG故事板任务
= 该SEG需要的参考图（按环节8的上传顺序）
+ 该SEG完整故事板提示词（环节8原文复制）
+ 一次图片模型生成任务
```

不同 SEG 不能混在同一次生成任务中；一个 SEG 一次任务。

## 故事板规格（固定）

- 一张故事板图片，**6 个独立画格，每格 9:16，2 行 3 列**，从左到右、从上到下、按时间顺序
- **一次生成一张完整故事板**——不允许分别生成 6 张单格图再由流程临时拼接
- 首格 = 段落进入状态，末格 = 段落退出状态，格与镜头 KFxx→SHxx 一一对应

## 执行五步

1. 每个 SEG 单独开一次生成任务（不要把整集的参考图和提示词塞进同一上下文）
2. 按环节 8 的「参考图上传顺序」逐张上传，**上传完成后逐张核对**：实际第 N 张 = 提示词中的 Image N
3. 原文复制该 SEG 的完整故事板提示词——不要另加通用人物/场景/负面/镜头/参考图说明提示词（已包含在内）
4. 生成
5. 技术检查（下节）

## 技术检查（自动可做，客观项）

```
图片是否成功生成
是否包含6个画格
画格是否按正确顺序排列
参考角色是否明显混用
是否存在严重肢体错误
是否缺失核心剧情节点
是否出现错误的连续状态
是否提前生成后续剧情结果（对照 forbidden_future）
是否出现大量错误文字
是否存在无法使用的画面损坏
```

**不进行自动审美评分**。构图不完美、表情不理想、光线不喜欢、镜头不震撼、褶皱有差异、群众不精细——这些**不触发重做**，进人工定向修改分支（环节11）。

## 固定标准

满足即固定：核心人物身份可辨认、无明显身份漂移、剧情顺序正确、关键状态变化完整、重要道具状态正确、场景空间基本一致、能衔接上一段退出状态、没有提前展示后续剧情、足以作为视频模型的视觉参考。

**不需要做到**：背景人物完全一致、碎片细节完全相同、群众面孔永久固定、细小特效与成片一致。

## 生成顺序与跨段核对

按剧情顺序 SEG01→SEGnn 生产。原因：后一段的进入状态需要核对**前一段已固定故事板**的退出状态。每固定一张，做一次配对核对：

```
SEGnn 退出（固定故事板末格）  ←→  SEGnn+1 进入（新故事板首格）
```

## 技术失败处理

| 情况 | 处理 |
| --- | --- |
| 生成失败/图片损坏 | 相同参考图+相同提示词重试，**自动，最多2次** |
| 参考图上传顺序错误 | 弃用当前输出，按正确顺序重传重生成（错误输出不得固定） |
| 缺格（要6格只出4格） | 修改输出结构指令，重生成，不进视频生产 |
| 人物身份明显混合 | 查 REFERENCE ROLE MAP → 减少无关参考图 → 强化唯一身份绑定 → 只重做受影响 SEG |
| 连续状态错误 | 查连续状态参考图是否正确上传 → 强化进入/退出状态描述 → 重做受影响 SEG，必要时同步重做后续依赖段 |

## 审核风险三级适配（平台内容审核拦截时）

**不改变剧情事实**，逐级降敏：

1. **原剧情版本**——直接用环节 8 原提示词
2. **镜头弱化版本**——只调表现方式：`动作准备 → 直接硬切 → 动作结果`（保留施动者/动作对象/动作结果/因果关系）
3. **结果叙事版本**——进一步降低接触画面：施动者做出动作 + 旁观者反应 + 结果已成。**因果不能改**（"少女被击倒"不能改成"少女自行晕倒"）

## 固定与登记

通过技术检查立即登记：状态=已固定、自动重新生成=关闭、自动审美复核=关闭、用途=对应15秒视频的唯一主视觉参考。**修改只能新建修订版本（V02），不得覆盖 V01。**

文件：`{项目编号}_EPxx_SEGxx_STORYBOARD_Vxx_FIXED.png`
注册表：`03_段落故事板/storyboard_registry.json`
生产记录（每张一条）：项目编号/集/段/日期/模型/参考图数量与实际顺序/版本/生成结果/技术检查/连续性检查/是否固定/问题备注/是否需人工修改。

# 环节 10：视频执行生成（纯执行节点）

## 环节定位（原文）

```
本环节不进行剧情分析。
本环节不重新生成分镜。
本环节不重新编写视频提示词。
本环节不修改人物、场景、道具和状态设定。
本环节只负责调用已经生产完成的内容生成视频。
```

一切检查规则、连续性要求、禁止内容都已写在环节 8 的提示词里——在执行环节重复它们属于流程冗余。

## 一段一条视频原则

```
一个15秒剧情段落 = 一张固定故事板 + 一份完整视频提示词 + 一次视频生成任务 + 一条固定15秒视频
```

不得把一个 SEG 拆成多条视频，不得把多个 SEG 合成一条长视频。

## 参考图原则

**默认只上传该 SEG 的固定故事板**，然后原文复制该 SEG 的完整视频提示词。

**不重复上传基础资产**（四视图/九视图/道具/连续状态图）——身份、空间、道具、状态信息已整合进固定故事板。多传反而造成：人物身份重新混合、故事板构图被资产图覆盖、模型把四视图误当视频画面、场景空间重构、关键帧顺序失效。

**辅助参考图**：只有当某个关键细节无法从故事板稳定读取时才允许加**一张**（系统界面文字、固定包装、关键伤口位置、特殊纹章、易被忽略的微小道具）。加时在提示词开头插入映射块：

```
参考图映射：
Image 1 = 本段固定故事板，控制所有镜头、人物、场景、构图、动作顺序和连续状态。
Image 2 = {辅助资产}，只控制{该细节}的结构与准确外观，不得改变故事板中的人物、场景和镜头顺序。
视觉优先级：Image 1 高于 Image 2。
```

## 执行动作

```
01. 读取当前SEG固定故事板
02. 读取当前SEG固定视频提示词
03. 故事板作为视觉参考上传
04. 提示词原文提交
05. 设置 15秒、9:16 竖屏、字幕关闭、水印关闭
06. 执行生成
07. 下载并保存结果 + 写生成记录
```

平台不能精确 15 秒时用最接近规格，拼接阶段统一裁切，不改剧情顺序。

按剧情顺序逐段执行；同一 SEG 在 V01 返回前不并行提交大量相同任务（版本难登记）。推荐节奏：生成 V01 → 检查 → 通过即固定 / 不通过进环节 11 定向修订。

## 结果处理

| 结果 | 处理 |
| --- | --- |
| 技术生成成功 | 状态=生成成功，进入环节 11（视频检查与问题定位） |
| 技术失败（报错/中断/损坏/打不开/时长为0） | 原故事板+原提示词不变，重新提交，**自动重试最多2次** |
| 内容存在问题（变脸/动作错/状态错/缺镜头/提前剧透） | **本环节不自动修改**——记录问题，交环节 11 人工判定 |

## 输出

每 SEG：视频文件 + 生成状态 + 使用的故事板版本 + 使用的提示词版本 + 平台返回信息。

文件：`{项目编号}_EPxx_SEGxx_VIDEO_Vxx.mp4`
注册表：`04_段落视频/video_registry.json`（segment_id / segment_video_id / video_file_ref / storyboard_id / storyboard_version / prompt_version / status）
