# 环节 11：视频检查与定向修订（人工环节）

自动生产不做内容质检；**内容质量判断在这里正式化为一个人工环节**。逐段看片，对照该段的固定标准与检查表，做三选一决策：固定 / 定向修订 / 重做。

## 视频固定标准

满足即固定：

```
核心剧情事件完整
人物身份基本稳定
关键动作因果清楚
进入状态和退出状态正确
关键道具状态正确
没有提前生成后续剧情
能够与前后SEG直接拼接
不存在严重技术损坏
```

**不要求**：背景群众面孔完全固定、特效细节完全一致、道具位置逐帧一致、每个镜头达到审美上限、群体对白逐人精确口型。

## 检查维度提示

- **状态连续**：对照 states.json——不可逆事实是否被违反（受损的不能自动恢复、被没收的不能重新出现、倒地的不能提前站起）
- **防剧透**：对照该段 `forbidden_future`——后续剧情元素是否提前出现
- **空间轴线**：各方是否保持既定方位与运动方向（如施压方始终从右向左）
- **持有关系**：道具持有人变化是否与分镜一致

## 问题三级分级

| 级 | 典型问题 | 处理 |
| --- | --- | --- |
| **一级·可接受轻微偏差** | 背景面孔变化、次要褶皱、尘土/电弧形状、镜头轻微偏移、群众数量小变 | **直接固定，不重做** |
| **二级·局部可修正** | 个别镜头表情不对、动作缺力度、道具位置轻微错误、节奏过慢、对白与动作略不同步 | **定向修订**：建该段 Vxx+1，只改相关时间区间，其余保留（见修订格式） |
| **三级·必须重做** | 核心身份错误、镜头顺序严重错乱、核心剧情节点缺失、因果被改（"被击倒"变"自行晕倒"）、不可逆状态违反、提前出现后续剧情 | 当前版本**不固定** → 先查固定故事板是否正确 → 再查视频提示词 → 修正后重做当前 SEG。**不自动重做其他无关 SEG** |

## 定向修订格式（二级问题）

不重新拆分提示词——仍提交一份完整视频提示词内容块，在原文开头增加修订目标：

```
本次修订目标：
只修正 {X.X}—{Y.Y} 秒 {对象} 的 {问题}。
保持 0.0—{X.X} 秒及 {Y.Y}—15.0 秒的剧情、人物、场景、动作顺序和连续状态不变。
{对象} 应 {正确表现}。
{对象} 不能 {禁止表现}。
```

结果存为新版本（V02/V03…），**旧版保留不覆盖**。

## 审核不通过处理

与环节 9 同一套三级适配（忠实制作 → 镜头降敏：动作准备→硬切→动作结果 → 结果叙事），**不修改剧情事实**。

## 深层问题的分层回溯

二级/三级问题若根源不在视频层，沿生产链上溯，改哪层重做哪层：

```
视频动作/对白/节奏问题     → 改视频提示词 → 仅重做该段视频
关键帧/构图/站位问题       → 改故事板提示词 → 重做该段故事板+视频
镜头数量/时间/节拍问题     → 改正式分镜 → 重新编译该段提示词（环节8）→ 重做故事板+视频
人物/场景/道具本身问题     → 改固定资产 → 查 asset_usage_index 找全部关联段 → 人工圈定重做范围
```

每次修订在 `06_生产提示词/05_人工修改记录/` 落一条：改了什么、为什么、重做了哪些文件、新版本号。

# 环节 12：排序拼接交付 + 生产包整理

## 排序与拼接

- 按 `episode_order` → `segment_order` 两级排序（读注册表，不依赖文件名字典序）
- 只拼接**已固定**的段视频；每段取**最新固定版本**
- 硬切直连：不加淡入淡出、不加溶解、不加黑场、不修改段内画面、不修改原始音频
- 平台生成时长不精确的段在此统一裁切

执行清单 `05_最终成片/EPxx_concat.txt`（ffmpeg concat 格式）：

```
file '../04_段落视频/EP01/PDZJ-001_EP01_SEG01_VIDEO_V01.mp4'
file '../04_段落视频/EP01/PDZJ-001_EP01_SEG02_VIDEO_V01.mp4'
...
```

```bash
ffmpeg -f concat -safe 0 -i EP01_concat.txt -c copy EP01_成片.mp4
```

`-c copy` 流拷贝优先；编码参数不一致导致失败再退回重编码。输出单集/整剧成片注册记录。

## 最终生产包

```
01_项目信息/
02_全剧资产/            + asset_usage_index.json（asset_id → 使用它的 segment 列表）
03_段落故事板/           全部版本保留
04_段落视频/             全部版本保留
05_最终成片/
06_生产提示词/
  ├── 01_资产生成提示词/
  ├── 02_段落故事板提示词/
  ├── 03_段落视频提示词/
  ├── 04_段落可编辑生产包/   每段自包含，人工修改的入口
  └── 05_人工修改记录/
```

每段可编辑生产包内容：原始剧情 / 剧情目标 / 必须剧情点 / 原始对白 / 进入与退出状态 / forbidden_future / 资产调用清单 / 正式分镜 / 故事板提示词 / 视频提示词 / 故事板与视频文件引用（含版本）。

## 执行层对接（执行器无关）

所有执行器消费同一套输入：环节 8 的 `tasks.json` + 提示词文件 + 固定故事板。

**方式一（默认）：Agent 直调中转站 API**
- 复用仓库 `utils.py`：`RespectConfig`（key 走 `RESPECT_API_KEY` 环境变量）、`api_request` 提交与轮询、`extract_image_payloads`/`extract_video_urls` 解析、`download_to_output` 落盘
- 循环：读 tasks.json → 按 `image_n` 顺序传参考图 → 提交 → 轮询 → 落盘到 `output` 路径 → Agent 读图做技术检查 → 通过则写注册表登记固定，技术失败原样重试 ≤2
- 内容问题不自动改：落记录，停在原地等人工（环节 11）

**方式二（备选）：ComfyUI 工作流**
- 工作流 A（故事板）/ B（视频）按 tasks.json 逐段 queue；多图输入顺序必须与 Image 编号一致
- 文件队列节点（`RespectStoryboardSave/Next/Complete`）：一段 = 一个任务
- 拼接可用 `RespectConcatVideos`

**方式三：手动网页操作**——按 tasks.json 逐段上传+粘贴提示词，产物放回 `output` 路径即可归队。

通用规则：数据上段间无依赖；**流程默认按剧情顺序跑**（每段固定前核对与上一段的衔接），接受错误传播风险时可并行提速。拼接环节按注册表顺序出 ffmpeg concat 清单执行。
