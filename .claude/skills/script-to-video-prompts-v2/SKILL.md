# AI短剧自动化生产体系（12环节定版）

把完整剧本处理成：固定资产库 + 每段多关键帧故事板 + 每段15秒视频提示词 + 可定点修改的生产包。

面向 AI 短剧：单集 1~5 分钟，最小生产单位 = 固定 **15 秒段落**。

> 这是 v2（12环节版）。与 v1（`script-to-video-prompts`，9步·首帧链方案）的关键差异见下表。两版并存期间，用户没点名版本时**默认用本版**。

## 与 v1 的三个关键差异

| 决策点 | v1（首帧链方案） | v2（本版） |
| --- | --- | --- |
| 段间衔接 | 首帧=上一段尾帧，删头0.8秒，段间严格串行 | **无首帧链**。连续性靠「上一段退出状态 = 下一段进入状态」（客观状态一致即可，不要求画面构图相同）。段与段**可并行生成** |
| 视觉参考 | 每镜头一张独立关键帧 | **每段一张多格故事板**（总图内多个9:16关键帧格，标注镜头编号） |
| 质量控制 | 多模态自动检查+自动重生成 | **不做审美检查、不自动重做成功结果**。客观技术检查（格数/顺序/身份混用/损坏）照做，技术失败自动重试≤2次；内容质量判断是人工环节（环节11），按 segment_id 定向修订出新版本，旧版不覆盖 |

## 四条最终原则（最高优先）

1. **整剧决定资产。** 不能根据局部片段随意定义资产；只有完整系列的分析结果才能成为 canonical 定论。
2. **资产负责「长什么样」，状态负责「此刻发生什么」。** 动作、表情、临时站位永远不做成资产。
3. **每段一张多关键帧故事板，故事板与正式镜头一一对应。**
4. **自动生产不检查、不重做；发现问题后按 segment_id 人工定点修改。**

另继承两条基础纪律：输出给 AI 看不给人看（干净、结构化、可直接复制）；一致性高于表现力。

## ID 体系

| 对象 | 格式 | 例 | 说明 |
| --- | --- | --- | --- |
| 项目编号 | 拼音/缩写-三位数 | `PDZJ-001` | 项目开工时定一次 |
| 集/段 | `EPxx-SEGxx` | `EP01-SEG03` | 两位数 |
| 人物资产 | `C{三位}-E{两位}-A{两位}` | `C001-E01-A01` | 实体-演化阶段-造型版本 |
| 场景资产 | `S{三位}-E{两位}` | `S001-E01` | 实体-环境版本 |
| 道具资产 | `P{三位}-ST{两位}` | `P003-ST02` | 实体-状态版本 |
| 附属资产 | `AT{三位}-{所属人物ID}` | `AT001-C001` | 胎记/疤痕/标志配饰等（格式为本 skill 约定，可调） |
| 镜头 | `SHxx` | `SH02` | 段内编号 |
| 关键帧格 | `KFxx` | `KF02` | 与镜头一一映射：KF02→SH02 |
| 生产文件命名 | `项目编号_集数_段落_内容类型_版本[_状态]` | `PDZJ-001_EP01_SEG04_STORYBOARD_V01_FIXED.png`、`PDZJ-001_EP01_SEG01_VIDEO_V01.mp4` | 修订出 V02，**旧版保留不覆盖** |

## 固定参数

| 项 | 值 |
| --- | --- |
| 段时长 | 固定 15 秒，9:16 竖屏 |
| 故事板 | 每段 1 张总图，**6 个 9:16 画格，2 行 3 列**，按时间序左→右上→下；一次生成整板，不单格拼接 |
| 故事板模型 | GPT Image 2（默认，可换） |
| 视频模型 | 即梦2（默认，可换） |
| 技术失败自动重试 | 最多 2 次（相同参考图+相同提示词） |
| 生成顺序 | 按剧情顺序 SEG01→SEGnn（便于逐段核对退出/进入状态；数据上无依赖，接受错误传播风险时可并行提速） |
| 成片拼接 | 硬切，不加转场/黑场，不改画面与音频 |

**调用资产必须用 asset_id，名称只给人看。**

## 生产执行是可替换模块（环节 9~10）

出图出片只是**生产工具的运用**，不属于流程逻辑。Agent 直调中转站 API、ComfyUI 工作流、平台手动操作——背后可能是同一个生图/生视频模型，选哪个不影响任何环节的定义。

模块契约：**进** = 环节 8 的 `tasks.json` + 提示词文件 + 固定故事板；**出** = 约定路径的文件 + 注册表登记。满足契约的任何执行器都可即插即用。

两个适配层不要混淆：

| 换什么 | 改哪里 | 影响范围 |
| --- | --- | --- |
| 换**执行器**（API/ComfyUI/手动） | 环节 9~10 的执行方式 | 流程逻辑零影响 |
| 换**生成模型**（即梦2→其他） | 环节 8 的提示词编译模板 | 仅环节 8，其余环节不动 |

## 唯一人工确认点

**环节 1 结束后停一次**：让用户确认「全剧时间轴 + 实体主表 + 项目视觉基调 + 解析范围标记」。

- 输入是完整系列 → 结论标 `canonical`
- 输入只有单集 → 结论标 `provisional`（后续集数到位后需复核升级）
- 测试片段 → 标 `test_sample`，资产结论只在测试命名空间生效，不进正式资产库

确认后 2~8 环节连续跑完，不逐步问「是否继续」。例外：用户说「只做环节 N」就只做那环节。

## 常见错误

- ❌ 只看一集就把资产定成 canonical → ✅ 单集只能 provisional
- ❌ 把动作/表情/站位做成资产 → ✅ 那是状态，进段落状态包
- ❌ 段记录里写人物名调资产 → ✅ 必须用 asset_id
- ❌ 上一段退出状态和下一段进入状态对不上 → ✅ 这是段间衔接的唯一机制，必须逐项核对
- ❌ 给生成结果做自动质检、自动重试 → ✅ 生成即固定，问题留给人工定点修改
- ❌ 生成候选组让人挑 → ✅ 每资产/每段只生成 1 个结果
