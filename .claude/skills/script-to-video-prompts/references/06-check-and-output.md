# 第8-9步：一致性检查 + 成片输出

这两步涉及实际的视频文件。这个 skill 负责**生成检查清单和拼接指令**，实际执行通常交给 ComfyUI 工作流或脚本。

# 第8步：一致性检查

## 8.1 方案

用多模态大模型自动审查生成出来的关键帧和视频片段。逐段对照资产库和段记录，输出结构化报告，支持自动触发重新生成。

## 8.2 六个检查维度

| 维度 | 查什么 | 对照物 |
| --- | --- | --- |
| 人物形象一致性 | 脸、发型、服装、标志性特征（疤痕/痣/配饰）是否与资产一致 | 资产文件的「稳定特征锁定」 |
| 场景状态一致性 | 空间布局、陈设、光源位置、磨损度 | 场景资产的「稳定特征锁定」 |
| 道具一致性 | 道具是否出现、位置和状态是否对 | 段记录的「关键道具及状态」 |
| 段落连贯性 | 上一段尾帧与本段首帧是否顺滑，物理痕迹是否继承 | 段记录的「连续性备注」 |
| 剧情逻辑 | 动作/对白/情绪是否与段记录一致，时间线是否合理 | 段记录的「动作时间线」「对白」 |
| 生成质量 | 手部畸形、多余肢体、面部扭曲、文字水印 | 【技术要求】的避错项 |

**「段落连贯性」是最容易出问题的维度**，因为它跨段。检查时必须同时加载上一段的尾帧和本段的记录。

## 8.3 报告格式

`06_检查报告/集01_check.json`：

```json
{
  "episode": "01",
  "checked_at": "<时间戳>",
  "segments": [
    {
      "segment": "01-05",
      "pass": false,
      "issues": [
        {
          "dimension": "人物形象一致性",
          "severity": "high",
          "asset": "C01-V03_受伤留疤",
          "detail": "第9秒起左脸疤痕消失",
          "action": "regenerate",
          "hint": "在视频提示词开头一致性句中强调「左脸颊2.5厘米浅褐色疤痕全程可见」"
        }
      ]
    },
    { "segment": "01-06", "pass": true, "issues": [] }
  ],
  "summary": { "total": 6, "passed": 5, "failed": 1 }
}
```

`severity`：`high` 必须重生成 / `medium` 建议重生成 / `low` 记录即可。

`action`：`regenerate`（重生成本段）/ `regenerate_keyframe`（只重出关键帧）/ `manual`（需人工介入）/ `accept`（可接受）。

`hint` 要给出**具体的提示词修改建议**，不要只说「不一致」——这是给自动重生成循环用的。

## 8.4 重生成循环

```
检查 → 有 high issue → 按 hint 改提示词 → 重生成该段 → 再检查
```

同一段连续失败 3 次就停下来标 `manual`，报给用户，不要无限循环。

# 第9步：成片输出

## 9.1 拼接规则

- **硬切**，不做转场、不做调色、不做任何后期
- 只拼接通过检查的片段
- 按段编号顺序拼接
- 拼接的是删过头的 `段XX.mp4`，不是 `段XX_raw.mp4`

## 9.2 目录与命名

```
项目根目录/
├── 00_全局设定/
│   └── visual_tone.md
├── 01_剧本解析/
│   └── segments.json
├── 02_资产库/
│   ├── 人物形象版本库/    C01-V01_日常家居.md ...
│   ├── 场景状态版本库/    S01-V01_夜晚整洁.md ...
│   └── 道具状态版本库/    P01-V01_公文包关闭.md ...
├── 03_分镜与提示词/
│   └── 集01/
│       └── 段01/
│           ├── storyboard.md
│           ├── image_prompts/    镜头01.txt ...
│           ├── keyframes/        镜头01.png ...
│           ├── video_prompt.txt
│           └── video_inputs.json
├── 04_生成视频/
│   └── 集01/
│       ├── 段01_raw.mp4     原始15秒
│       └── 段01.mp4         已删头0.8秒，约14.2秒
├── 05_成片/
│   └── 集01_成片.mp4
└── 06_检查报告/
    └── 集01_check.json
```

集号段号一律两位数。

## 9.3 拼接指令

生成一份可直接执行的拼接清单 `05_成片/集01_concat.txt`（ffmpeg concat 格式）：

```
file '../04_生成视频/集01/段01.mp4'
file '../04_生成视频/集01/段02.mp4'
file '../04_生成视频/集01/段03.mp4'
```

对应命令：

```bash
ffmpeg -f concat -safe 0 -i 集01_concat.txt -c copy 集01_成片.mp4
```

用 `-c copy` 直接流拷贝，不重编码——硬切拼接不需要重编码，也能避免二次压缩损失。

如果各段编码参数不一致导致 `-c copy` 失败，再退回重编码。

## 9.4 与 ComfyUI 的对接

这一步的产物可以直接喂给仓库里已有的节点：

- `video_prompt.txt` 的内容 → 视频生成节点的 prompt 入参
- 多段视频拼接 → `RespectConcatVideos`
- 删头 0.8 秒 → `RespectTrimVideoFile`
- 分镜任务队列 → `RespectStoryboardSave` / `RespectStoryboardNext` / `RespectStoryboardComplete`

`RespectStoryboardSave` 吃 JSON 数组格式的 `prompts_json`，所以如果要走队列，把一集所有段的 `video_prompt.txt` 汇总成一个 JSON 数组即可。
